# 深度概念解剖

明确进入深度解剖时使用。保留原有八个方向，最终将切面压成一句清楚的理解；不因材料缺失编造词源、历史或学术结论，某方向缺依据时保留该方向并说明限制。

## 定锚

确认最通行的定义、常见误解与核心词素。区分概念的不同学科含义，不把多个含义强行揉成一个。

## 八维

每个方向用必要的短段说明，不要求凑满句数。

1. **历史**：最早可核实的来源、演变及关键转折。
2. **辩证**：相对概念、冲突和条件化的综合理解。
3. **现象**：用日常场景还原概念；说明场景与真实机制的对应和限制。
4. **语言**：有依据的词源、相邻概念与隐喻；不能从词形猜造历史。
5. **形式**：适用时给公式或形式化表达，并解释变量、成立条件和失效处；不适合公式时保留这一维并解释原因。
6. **存在**：它怎样影响人的实践和理解；哲学判断与事实分开。
7. **美感**：用具体意象辅助理解，标为比喻，不当作证据。
8. **元反思**：现有隐喻挡住了什么，换一种解释能看到什么。

## 内观与压缩

内观可用第一人称思想实验呈现概念，说明这是解释性比喻。随后提炼八维共同的深层结构。

压缩保留三项：概念关系式、最简单的一句话、结构图。关系式可以是概念等式，不假称数学定理。原笔记模式的图形线条保留纯 ASCII，标签可以用中文；用 org 原生的 `#+begin_example` 与 `#+end_example` 包住结构图，保留换行、空格与对齐，不改用 Markdown 代码围栏。

## 原笔记格式

在 org-mode 笔记交付中使用其原生语法：加粗 `*bold*`，代码 `~code~` 或 `=code=`，标题用星号层级，不混入 Markdown 标题、粗体或代码围栏。聊天交付可以使用本轮指定的格式。

```org
#+title: 概念解剖：{概念名}
#+filetags: :concept:
#+date: [YYYY-MM-DD]

* 定锚
* 八刀
** 历史
** 辩证
** 现象
** 语言
** 形式
** 存在
** 美感
** 元反思
* 内观
* 压缩
```

获取真实的当前日期和时间。保存目录按以下顺序确定：用户本轮指定的位置；否则环境变量 `LJG_NOTES_DIR`（可由用户自行配置）；两者都没有时使用 `~/Documents/notes`。文件名为 `{timestamp}--概念解剖-{概念名}__concept.org`，时间戳格式为 `YYYYMMDDTHHMMSS`。目录不存在时先说明再创建，或改为交付可复制内容。写入前核对目标，必要时安全处理概念名中的路径分隔符，不覆盖现有笔记。仅在成功保存后提供实际路径；没有保存能力时明确说明缺口。
